## 1. What Was Done

### Parsers (`backend/app/services/import_engine/parsers/`)

- `base.py` — `ParsedRow` dataclass + `BankParser` ABC + shared utilities (`_to_decimal`, `_eu_str_to_decimal`, `_parse_dmy_slash`, `_parse_dmy_hyphen`, `_parse_dmy_dot`, `_parse_dmy_hhmm`, `_to_date`, `_str_or_none`, `_serialize_row`, `_is_na`)
- 12 bank parser classes, one per bank, all following Spec 16:
  - `AbancaParser` — openpyxl, header=4, YYYY-MM-DD
  - `BBVAParser` — openpyxl, header=15, DD/MM/YYYY, IBAN extraction from row 7
  - `BancaMarchParser` — openpyxl, header=3, mixed date format (DD/MM + full datetime), year-repair logic for short dates
  - `BankinterParser` — openpyxl, header=5, YYYY-MM-DD, optional REF. 16 column
  - `CaixaBankParser` — xlrd, header=2, graceful empty-file handling (SIN MOVIMIENTOS)
  - `CajamarParser` — calamine engine, header=0, Concepto split on first `\n`
  - `DeutscheBankParser` — xlrd, header=5, DD.MM.YYYY dots, European string amounts, IBAN extraction, handles both `DEUSTCHE_` and `DEUTSCHE_` filename prefixes
  - `EurocajaRuralParser` — CSV, utf-8-sig, `;` separator, skiprows=8, European amounts with €, IBAN extraction
  - `IbercajaParser` — openpyxl, header=6, DD-MM-YYYY hyphens, Referencia float→int string
  - `RuralviaParser` — openpyxl, header=3, datetime objects with time → `.date()`, IBAN extraction
  - `SabadellParser` — calamine engine, header=7, DD/MM/YYYY
  - `SantanderParser` — openpyxl (.xlsx) / xlrd (.xls), header=7, dynamic sheet iteration for multi-sheet LMS 3917.xls, NO HAY MOVIMIENTOS detection, Hoja1 skip
- `__init__.py` — exports all parsers + `ALL_PARSERS` singleton list

### Pipeline (`backend/app/services/import_engine/`)

- `detector.py` — `detect_parser(filename)`: returns the right parser by filename prefix; raises `ValueError` for unknown files
- `deduplicator.py` — `file_hash(bytes)`: SHA-256 of file bytes; `movement_hash(bank_account_id, value_date, amount, description)`: SHA-256 of pipe-joined canonical fields
- `normalizer.py` — `normalise(row, ...)`: maps `ParsedRow` → `dict` of Movement fields; `description_detail` is appended to `description` with ` | ` separator so it remains searchable for classification
- `import_service.py` — `run_import(...)`: full async pipeline (file dedup → parser detection → temp file parse → RawMovement insert → Movement dedup + insert → ImportBatch finalization)
- `__init__.py` — re-exports `run_import`, `detect_parser`, `file_hash`, `movement_hash`

### Router (`backend/app/routers/imports.py`)

Three endpoints:
- `POST /api/v1/imports/` — multipart file upload + `bank_account_id` Form field → triggers full pipeline → returns `ImportBatchResponse` (201)
- `GET /api/v1/imports/` — list batches, filterable by `company_id` / `bank_account_id`, limit=50
- `GET /api/v1/imports/{batch_id}` — get single batch

### Tests (`backend/tests/test_import_engine/test_parsers.py`)

- One test per bank (parametrized for multi-file banks) against actual sample files
- Known-empty CaixaBank file (LMS 5705) has explicit zero-row assertion
- Santander multi-sheet XLS test asserts merged output > 1 row
- Full detector test: all 12 filename prefixes → correct bank_name
- Deduplicator tests: deterministic hash, different inputs produce different hashes

## 3. Architecture Decisions

### description_detail → description concatenation
`Movement` model has no `description_detail` field. Rather than add a migration, the normalizer appends `description_detail` to `description` with ` | ` separator. This ensures all text is searchable when the classification engine does keyword matching.

### ParsedRow vs RawMovement (DB model)
`ParsedRow` is a pure Python dataclass — lives only in memory during parsing. `RawMovement` is the ORM model. The import service converts ParsedRow → RawMovement (DB) after parse, preserving `raw_row` dict as JSON audit trail.

### Temp file strategy
The import service writes file bytes to a `tempfile.NamedTemporaryFile` before parsing (parsers need a file path, not bytes). The temp file is always cleaned up in `finally`.

### File-level vs row-level deduplication
Two independent guards:
1. `file_hash` on ImportBatch — same file re-uploaded → status DUPLICATE, no rows processed
2. `movement_hash` per row — same movement from a different file → row skipped (SKIPPED status on RawMovement)

## 4. Known Limitations / Future Work

- No bank accounts are seeded yet. The `POST /imports/` endpoint requires a valid `bank_account_id`. Before importing real files, bank accounts must be seeded (Milestone 1.3 or earlier).
- Tests require the sample files to be present at `/samples/bank_statements/` — they are not committed to git. Run tests on the machine with samples.
- `python-calamine` must be installed for Cajamar and Sabadell parsers. It is in `requirements.txt`.
- The `extract_account_iban()` methods are implemented for BBVA, Deutsche Bank, Eurocaja Rural, and Ruralvia but are not yet used by the import service (Phase 1 requires explicit `bank_account_id` from the user).
