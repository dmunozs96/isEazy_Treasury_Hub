### Backend — Router (`backend/app/routers/analytics.py`)

New endpoint: `GET /api/v1/analytics/consistency?year=YYYY&month=M`

Both params default to the current month if omitted.

**Section A — Import Completeness:**
- Queries all active `bank_accounts` (joined to `companies`)
- Gets movement COUNT, MIN/MAX `value_date` per account for the selected period
- Gets last `imported_at` from completed `import_batches` per account
- Status logic:
  - `MISSING` = no movements in period
  - `PARTIAL` = has movements but `latest_movement < period_end - 3 days`
  - `OK` = otherwise
- Sorted: MISSING → PARTIAL → OK, then by company+account name

**Section B — Balance Reconciliation:**
- Runs only for accounts that have at least one `balance_after` value
- Opening balance = last `balance_after` before period start
- Closing balance (bank) = last `balance_after` within period
- Computed closing = opening + SUM(amounts in period)
- Delta = bank - computed
- Status: `OK` (|Δ| ≤ 0.01€) | `WARNING` (|Δ| ≤ 50€) | `ERROR` (|Δ| > 50€) | `NO_DATA`
- Sorted: ERROR → WARNING → NO_DATA → OK

**Section C — Data Quality Warnings:**
- C1 HoldCo revenue: movements on `is_holding=True` company accounts with `category_code = 'OCF_INCOME'` (all time)
- C2 High unclassified: companies where `UNCLASSIFIED / total > 15%` in the period
- C3 Unresolved IC: COUNT of `MatchStatus.UNRESOLVED` matches
- C4 IN_TRANSIT timeout: COUNT of `MatchStatus.IN_TRANSIT` matches where `transit_expires_at < now()`

## 3. Design Notes

**Section B N+1 risk:** The balance reconciliation loop issues 3 queries per account with `balance_after` data. In Phase 1 with ~90 accounts and only a subset having balance data, this is acceptable. If performance degrades, refactor to use window functions.

**Section A "Partial" heuristic:** The 3-day grace window for partial coverage handles weekends at the end of the month without over-flagging.  For example, a month ending on Friday would flag Saturday/Sunday as missing without the grace period.

**HoldCo revenue check:** Runs across all time (not period-scoped) since a HoldCo income is always suspicious regardless of when it occurred. If this produces too much noise once real data is loaded, scope it to the last 90 days.

---

## 4. Known Limitations / Deferred

- Section A does not detect intra-month gaps (e.g., 2 weeks missing in the middle). It only checks if the last movement is near the period end.
- Section B requires `balance_after` to be populated by the bank parser. Banks that don't export running balance (some Eurocaja Rural/Ruralvia) will show `NO_DATA` and are excluded from reconciliation.
- No "expected accounts per company" registry — Section A shows all registered accounts but cannot flag if an account was never registered at all.
