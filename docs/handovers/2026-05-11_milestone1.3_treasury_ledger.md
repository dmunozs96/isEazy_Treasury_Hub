## 1. What Was Done

### Backend — `backend/app/schemas/movement.py`

Replaced the stub schema with two new types:

- **`ClassificationInfo`** — lightweight classification view embedded in movement responses: `category_code`, `category_name`, `cash_flow_section`, `subcategory_code`, `source`, `is_confirmed`, `classified_at`, `override_reason`
- **`MovementResponse`** — now includes `company_short_name` and `bank_name` (denormalized via JOIN) plus `classification: ClassificationInfo | None`
- **`ClassificationOverride`** — request body for the category PATCH endpoint

### Backend — `backend/app/routers/movements.py`

Full implementation replacing the stub. Four endpoints:

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/v1/movements/` | List with filters + pagination + sort |
| `GET` | `/api/v1/movements/export` | Excel download (max 10,000 rows) |
| `GET` | `/api/v1/movements/{id}` | Single movement detail |
| `PATCH` | `/api/v1/movements/{id}/category` | Inline category override |

Key design choices:
- **4-table JOIN**: `Movement` → `Company` → `BankAccount` → `MovementClassification` → `CategoryTaxonomy` (all LEFT OUTER JOINs) so unclassified movements still appear
- **Route order**: `/export` is declared before `/{movement_id}` to prevent FastAPI matching "export" as a UUID
- **Count query** uses only `Movement` + `MovementClassification` JOIN (no company/bank/taxonomy joins needed for counting)
- **Sort columns**: `value_date` (default, desc), `amount`, `accounting_date`
- **Excel export**: styled headers (navy fill, white bold text), auto-sized columns, Spanish column names, openpyxl (already in requirements)
- **Category override**: validates category code exists → upserts `MovementClassification` row (sets `source=MANUAL`, preserves `previous_category_code` for audit trail)

Filter params on list/export:
`company_id`, `bank_account_id`, `date_from`, `date_to`, `category_code`, `amount_min`, `amount_max`, `search` (ilike on description / counterpart_name / reference)

### Backend — `backend/app/routers/classifications.py`

Added `GET /api/v1/classifications/categories` — returns all active `CategoryTaxonomy` rows ordered by level then code. Used by the frontend category dropdown.

New `CategoryResponse` Pydantic schema defined inline in the router (no separate schema file needed at this stage).

### Frontend — `frontend/lib/api/movements.ts` (new file)

```typescript
movementsApi.list(filters)            // GET /movements/ paginated
movementsApi.get(id)                  // GET /movements/{id}
movementsApi.overrideCategory(id, body) // PATCH /movements/{id}/category

```

`toQueryString()` helper builds URLSearchParams, omitting undefined/null/"" values.

### Frontend — `frontend/app/ledger/page.tsx`

Full client-side Treasury Ledger page. Features:

**Filter bar:**
- Search input with debounce (400ms) — searches description, counterpart name, reference
- Date range: two `<input type="date">` fields + quick shortcuts (7d / 30d / Month)
- Company filter: `<select>` from live companies list; single-company filter passed to API
- Category filter: `<select>` from live taxonomy list
- Reset button: resets global date/company filters + local search/category

**Table (TanStack Table v8 `useReactTable`):**
- Columns: Fecha | Empresa | Banco | Descripción | Importe | Categoría | Saldo Post.
- `manualPagination: true` — all filtering/sorting/paging is server-side
- Amount column: green (`text-emerald-700`) for inflows, red (`text-red-600`) for outflows
- `isFetching` indicator shows "Cargando…" during refetches (keeps previous data visible via `placeholderData`)

**Inline category edit (`CategoryCell` component):**
- Clicking the category badge (pill) switches to a `<select>` dropdown with all taxonomy options
- On selection: calls `overrideCategory` mutation → invalidates `movements` query → table refreshes
- On blur without selection: exits edit mode
- Badge colour by cash-flow section: OPERATING=blue, INVESTING=purple, FINANCING=orange, INTERNAL=slate, UNCLASSIFIED=yellow

**Pagination:**
- Previous/Next buttons + page number pills with ellipsis logic
- Page count from API response (`data.pages`)

**Export:**
- "Exportar Excel" button → `window.open(exportUrl)` → browser downloads the xlsx file directly

## 3. Known Limitations / Future Work

- **No bank accounts seeded yet.** The `POST /imports/` and all movement queries assume bank accounts exist. First run requires seeding (see TODO.md).
- **Single company filter.** The API accepts only one `company_id`. Multi-company filter in the UI sends the first selected company or nothing. Can be extended to accept `company_ids[]` in Milestone 1.4+.
- **No column-click sorting.** Default sort is `value_date desc`. Sortable columns can be added by wiring `manualSorting` to the table state.
- **No row detail panel.** Clicking a row does not open a detail view. This can be added later.
- **Classification seed required.** Until the Classification Engine (Milestone 1.4) is built and seeds run, all movements show UNCLASSIFIED. Inline edit works immediately once categories are seeded.
